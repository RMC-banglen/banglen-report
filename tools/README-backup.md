# สำรองและกู้ข้อมูล RMC บางเลน

ข้อมูลจริงอยู่ใน Supabase (ไม่ได้อยู่ใน GitHub) — ไฟล์สำรองมีชื่อลูกค้าและ PIN ผู้ใช้ **ห้ามใส่ใน repo นี้ (สาธารณะ)**

## สำรอง

| วิธี | ได้อะไร | ทำอย่างไร |
|---|---|---|
| ปุ่มบนหน้าเว็บ (ผู้ดูแลระบบ) | ไฟล์ `RMC-banglen-backup_วันที่_เวลา.json` ทุกตาราง (ไม่มีรูป) ลงโฟลเดอร์ดาวน์โหลด · เตือนว่าไม่ได้สำรองมากี่วัน | กด "สำรองข้อมูลตอนนี้" |
| สคริปต์ในเครื่อง | โฟลเดอร์ `D:\Claude AI\banglen-backups\data\<วันที่>` ทุกตาราง + `photos\` รูปถ่ายทั้งหมด | ดับเบิลคลิก `tools\backup-supabase.bat` |

## กู้

ทำได้จากสคริปต์ในเครื่องเท่านั้น (ไม่มีปุ่มกู้บนหน้าเว็บ) ต้องใส่ PIN ผู้ดูแลระบบ และพิมพ์ `RESTORE` ยืนยัน

```
node tools/restore-supabase.cjs <ไฟล์.json หรือโฟลเดอร์สำรอง>                  # ดูผลเฉยๆ (ไม่เขียนอะไร)
node tools/restore-supabase.cjs <สำรอง> --apply                               # ใส่เฉพาะแถวที่หายไป (ไม่ทับของเดิม)
node tools/restore-supabase.cjs <สำรอง> --apply --overwrite                   # ทับแถวที่มีอยู่ด้วยค่าจากไฟล์สำรอง (ข้อมูลที่แก้หลังสำรองจะหาย)
node tools/restore-supabase.cjs <สำรอง> --tables concrete_results,foreman_reports --apply   # เฉพาะบางตาราง
```

- ก่อนเขียน สคริปต์เก็บสถานะปัจจุบันไว้ที่ `...\banglen-backups\pre-restore\<เวลา>\` (กู้ย้อนกลับได้)
- ไม่ลบอะไรเลย · ตารางที่ไม่มีคอลัมน์ `id` ข้าม (ต้องกู้เอง)
- หลังกู้ ให้รันไฟล์ `restore-fix-sequences.sql` (อยู่ในโฟลเดอร์ pre-restore) ใน Supabase SQL editor เพื่อให้เลข id อัตโนมัติไม่ซ้ำ
- **ไม่รวม:** โครงสร้างตาราง (สร้างจาก `supabase-*.sql` ใน repo ก่อน) และรูปถ่าย (อัปโหลดจาก `photos\` ของโฟลเดอร์สำรอง)
- ทดสอบตรรกะกับฐานข้อมูลจำลองแล้ว (ใส่เฉพาะที่หาย / ทับ / ปฏิเสธ PIN ผิด / ยกเลิกเมื่อไม่ยืนยัน) **ยังไม่เคยกู้ลง Supabase จริง**
